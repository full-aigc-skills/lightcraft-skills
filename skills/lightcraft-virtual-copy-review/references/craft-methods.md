# 独立虚拟副本审稿：实际方法与参数

先执行`lightcraft-cli commands --json`及`lightcraft-cli describe 命令ID`，以当前版本回执核对能力。完整参数在[配方](craft-steps.json)，实际枚举在[命令记录](craft-command-evidence.json)，GitHub固定来源见[来源记录](workflow-sources.json)。

## CLI同进程执行

`lightcraft-cli run --library 新建或已核实的库 --import 工作区照片 --script -`从stdin逐行接收`{"command":"...","params":{...}}`。已有库仅在需要时导入，先查询后绑定真实ID。复制粘贴需同一个run进程；示例中的`$`是Agent手动绑定模板，不是CLI变量。每行检查ok和error，有失败停止依赖步骤，不把退出码当图像效果。

## 插件MCP会话

先读取`lightcraft-editor`实际工具schema。当前插件工具为`command_run {"id":"develop.get","params":{"id":实际照片ID}}`，与原生MCP工具名可能不同。`open_file`用于工作区素材导入；随后`inspect`和真实命令回执核对图库与active，不能把独立CLI库当成已打开的Web库。只有当前Web实际暴露并成功执行相应命令时才走同画面操作，否则明确仅CLI可用，不绕用SDK声称宿主同步通过。`command_list`不支持的错误回执不授权猜命令；先用查询验证无副作用的方法，再按当前后端能力执行。

## 参数绑定与编辑保护

原片及非目标设置不变，副本copyOf指向源ID，实际导出像素发生变化且新进程重开一致。

这是共享原文件的独立目录项，不是物理备份。不能把暗片提亮预设当成自动修复；不删除原片或副本。创建不是幂等操作，超时先查询copyOf和名称，避免重复创建。

库目录要完整保留，包括目录元数据及原照片引用；PNG是审稿派生图，不是可继续编辑的库。源照片不变不等于库自动备份。独立进程重开时再次绑定ID并核对设置和实际像素，单凭相同路径返回不能证明重载。

曝光示例为绝对0.7EV，不是追加0.7，也不保证真实图像不过曝。完成后查看高光、阴影、肤色与裁切；合成像素验证不代表真实照片审美或RAW色彩已验收。

## Web图库交付与真实重载

固定官方Web0.8.0支持`command_run {"id":"file.backupLibrary","params":{}}`下载完整图库ZIP。这是Web专用动作，原生CLI目录没有它；不要调用`save_project`伪造单文件库，也不要用`save_file`推断不存在的虚拟文件API。`started:true`只表示已启动，等待宿主实际写出下载文件，再检查文件存在、ZIP完整性、library目录及originals内容，记录实际返回/写入路径。当前适配器把下载保存到工作区craft-exports并加唯一前缀，不能按所传app.export路径直接假设宿主同名文件已生成。

浏览器库依赖当前站点存储，保留原片和完整备份。页面重新加载后再次查询照片与版本、导出审稿图并比对像素；恢复ZIP是另一项操作，只有实际通过时才能声明恢复验收。命名版本列表可能自动包含日期版本，必须按唯一名称查索引，不能把第一个版本当成本次基线。

本批限定验收：官方0.8.0的macOS/Windows原生合成回归通过；隔离真实Codex MCP和内嵌浏览器已观察副本曝光、命名版本恢复、目标曲线迁移和页面重载持久化。实际图库备份由独立CLI读回三个照片的设置，与宿主一致；这不代表真实照片质量、Web备份恢复UI或所有宿主已验收。
