## Purpose

为 Lightcraft 多平台与 ArtCraft定义独立的运行与证据门禁，防止基础照片闭环、源码存在或结构测试被扩展为未经实际验证的产品支持声明。

## ADDED Requirements

### Requirement: SEXT3-1 每个平台真实固定制品、签名/依赖与目标运行

系统 SHALL 验证每个平台真实固定制品、签名/依赖与目标运行；证据 MUST 绑定当前版本、执行模式、输入和实际产物。未执行或依赖缺失 SHALL 保留开放状态，不由基础任务替代。

#### Scenario: 缺少该门禁证据
- **WHEN** 只有源码、文档或其他路径的通过报告
- **THEN** 本要求保持未验证，报告实际缺口而不声明已支持

### Requirement: SEXT3-2 ArtCraft 的三领域协议、依赖版本及变更失效规则

系统 SHALL 验证ArtCraft 的三领域协议、依赖版本及变更失效规则；证据 MUST 绑定当前版本、执行模式、输入和实际产物。未执行或依赖缺失 SHALL 保留开放状态，不由基础任务替代。

#### Scenario: 缺少该门禁证据
- **WHEN** 只有源码、文档或其他路径的通过报告
- **THEN** 本要求保持未验证，报告实际缺口而不声明已支持

#### Scenario: 跨领域任务及来源版本漂移
- **WHEN** 接收 craft-task/v1 的 Lightcraft、Designcraft 或 Printcraft 任务，且协议/schema 摘要、可信运行时兼容表、payload 摘要或输入版本不匹配
- **THEN** 原生执行之前拒绝；不从任务自身声明推导受信版本，不自动安装或升级依赖

#### Scenario: 素材身份冲突或路径外逃
- **WHEN** 相同 assetId/version 对应不同摘要，产物/工程/证据文件改变，或交付路径外逃
- **THEN** 拒绝交接；保持源输入，不能用文件名、目录移动或摘要重算掩盖版本冲突

#### Scenario: 依赖变化只失效消费者
- **WHEN** 节点 payload、明确输入版本/摘要、原工程修订、运行时/能力身份、授权或预算改变
- **THEN** 失效改变节点及其传递消费者，保留无关节点；图缺失、重复边、循环或同版本不同摘要一律拒绝，失效计算不能自动重放原生任务

### Requirement: SEXT3-3 选择性重建和移动交付的输入/产物及设备验收

系统 SHALL 验证选择性重建和移动交付的输入/产物及设备验收；证据 MUST 绑定当前版本、执行模式、输入和实际产物。未执行或依赖缺失 SHALL 保留开放状态，不由基础任务替代。

#### Scenario: 缺少该门禁证据
- **WHEN** 只有源码、文档或其他路径的通过报告
- **THEN** 本要求保持未验证，报告实际缺口而不声明已支持

#### Scenario: 显式选择性原生重建
- **WHEN** 已核验的三领域基线中曝光计划改变，调用方明确授权这一轮原生验收
- **THEN** 执行前绑定完整新计划和失效集合，只执行 photo/layout/pdf，复用 photo-import；保留基线输入和产物摘要，拒绝基线漂移、运行时漂移或无实际变化的重跑
- **AND** 记录实际执行节点、复用节点、前后输入/产物身份、逐步骤回执与独立重开；不将选择性重建证明扩展为移动设备验收

#### Scenario: Linux 官方发布树与固定 CLI 安装
- **WHEN** 在 Linux aarch64 或 x86_64 上显式安装固定 0.2.1 官方 tar.gz 发布包中的 CLI
- **THEN** 下载前核对版本、平台及精确资产名，解包前核对 archive SHA256 并拒绝目录外逃、重复成员、链接、特殊文件和过大归档；执行前核对 CLI SHA256，只安装 CLI 与许可到独立目录，不安装桌面程序或修改 PATH
- **AND** 原生版本、依赖、导入/显影/导出与独立重开结果按实际目标记录；容器结果仅证明记录的 Linux 用户空间，不替代其他平台、桌面或移动验收

#### Scenario: Windows 固定 portable CLI 与进程架构
- **WHEN** 显式在 Windows x64 或 x86 Python 进程安装固定 0.2.1 portable 制品
- **THEN** 使用实际进程位数区分 x64/x86，核对精确资产名、归档和 CLI SHA256，安装 .exe 与许可到独立目录，通过操作系统文件锁保证互斥，不修改 PATH 或安装桌面程序
- **AND** Windows 原生导入、显影、六份导出、解码和独立重开必须在 Windows CI 实际执行；x86 在 x64 主机运行须记录主机与进程身份，ARM64 无锁定制品时保持不支持
- **AND** 超时仅确认启动进程的终止请求，保持 UNKNOWN，不能声称后代进程全部停止或自动重放

#### Scenario: Windows 隔离 Python 的文本编码
- **WHEN** 以 python -I 在默认 cp1252 的 Windows 进程读取中文技能资料、计划与回执
- **THEN** 文件与子进程协议使用显式 UTF-8，JSON 标准输出使用可跨 locale 解码的转义形式；不得依赖被隔离模式忽略的 PYTHONUTF8 环境变量

#### Scenario: 移动交付保留输入及产物身份
- **WHEN** 显式把已核验的三领域产物交付包复制到已授权 Android 设备
- **THEN** 保留原图、产物、原生工程引用和来源报告的字节身份，交付包只使用受控相对路径；缺失引用、摘要漂移、链接、路径外逃和覆盖已有目标均在传输前拒绝
- **AND** 记录实际设备/系统、接收文件摘要、实际查看器及 PNG/PDF 显示证据；包校验、设备传输、视觉查看与原生工程设备端编辑分别登记，不用其中一层冒充另一层
